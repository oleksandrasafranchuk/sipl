# SIPL Toolkit

Інструменти для мови SIPL: синтаксичний аналіз, дерево виводу, семантичні терми, обчислення програм на станах і перевірка коректності циклічних програм.

## Встановлення

Потрібен Python 3.10 або новіший, сторонніх бібліотек немає. Для дерева у форматі SVG потрібен Graphviz.

```bash
git clone https://github.com/oleksandrasafranchuk/sipl.git
cd sipl
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
pytest
```

## Команди

```bash
sipl check examples/gcd.sipl                          # перевірка синтаксису
sipl parse examples/gcd.sipl                          # AST
sipl tree  examples/gcd.sipl -f text                  # дерево виводу: text, json, dot, svg
sipl term  examples/gcd.sipl                          # семантичний терм
sipl eval  examples/gcd.sipl -s "M=8, N=16" --trace   # обчислення на стані
sipl prove examples/gcd.sipl examples/gcd.spec        # перевірка коректності
```

Ключ `-o файл` записує результат у файл замість виводу на екран.

## Як працює програма

```
текст ──► лексер ──► парсер ──► дерево виводу ──► AST ──► семантичний терм ──► обчислення на стані
                                      │                          │
                                      ▼                          ▼
                                візуалізація            перевірка коректності
```

Кожен етап використовує результат попереднього. Парсер, побудова терму та обчислення реалізовані один раз, а візуалізація і перевірка коректності їх лише викликають.

### 1. Лексер (`lexer.py`)

Лексер розбиває текст на лексеми: ключові слова (`begin end if then else while do skip`), змінні, числа та знаки `:= ; + – * ( ) = > ¬ ∨`. Замість `¬` і `∨` можна писати `not` і `or`. Кожна лексема запам'ятовує свою позицію: рядок і колонку.

### 2. Парсер і AST (CORE-02) — `parser.py`, `parse_tree.py`, `ast.py`

Граматика SIPL:

```
P ::= begin S end
S ::= x:=a | S1;S2 | if b then S1 else S2 | while b do S | begin S end | skip
a ::= n | x | a1+a2 | a1–a2 | a1*a2 | (a)
b ::= a1=a2 | a1>a2 | b1∨b2 | ¬b | (b)
```

Ця граматика неоднозначна, тому парсер дотримується двох правил:
- усі бінарні операції лівоасоціативні;
- пріоритети від найвищого до найнижчого: `*`, `+ –`, `= >`, `¬`, `∨`, `:=`, `while`, `if`, `;`.

| Запис | Як розбирається |
|---|---|
| `X+Y*Z` | `X+(Y*Z)` |
| `A–B–C` | `(A–B)–C` |
| `¬M=N` | `¬(M=N)` |
| `if b then S1 else S2; S3` | `(if b then S1 else S2); S3` |

Парсер написаний вручну методом рекурсивного спуску і працює у два етапи:

1. **Дерево виводу.** Вершини — нетермінали граматики (`<програма>`, `<оператор>`, `<вираз>`, `<умова>`, `<змінна>`, `<число>`) і термінали. Кожна вершина зберігає назву застосованого правила:

   | Назва | Правило |
   |---|---|
   | NP1 | `<програма> ::= begin <оператор> end` |
   | NS1–NS6 | присвоєння, `;`, `if`, `while`, `begin…end`, `skip` |
   | NA1–NA6 | число, змінна, `+`, `–`, `*`, `(вираз)` |
   | NB1–NB5 | `=`, `>`, `∨`, `¬`, `(умова)` |
   | NV, NN | змінна, число |

2. **AST.** Дерево виводу перетворюється на власні вузли: `Program`, `Assign`, `Seq`, `If`, `While`, `Block`, `Skip`, `BinA`, `Cmp`, `Or`, `Not`, `Num`, `Var`.

Кожна вершина і кожен вузол мають `SourceSpan`: початок, кінець, рядок і колонку свого фрагмента тексту.

Синтаксична помилка повідомляє місце і підказку:

```console
$ sipl check bad.sipl
bad.sipl:3:1: помилка: після «;» очікувався оператор, а знайдено «end»
     3 | end
       | ^^^
  підказка: у SIPL «;» розділяє оператори (S1;S2), тому перед end крапка з комою не ставиться
```

### 3. Дерево виводу (VIS-01) — `visualization/parse_tree_view.py`

Дерево будується з результату парсера і виводиться у чотирьох форматах:

| Формат | Що отримуємо |
|---|---|
| `text` | дерево в терміналі: правило, позиція і фрагмент коду у кожній вершині |
| `json` | структура дерева; у кожній вершині є `span` і текст фрагмента |
| `dot` | граф для Graphviz; у підказці вершини — правило, позиція і фрагмент |
| `svg` | зображення дерева (через Graphviz) |

```console
$ sipl tree examples/power.sipl
<програма> [NP1]  1:1  «begin R := 1; while Y > 0 do begin R …»
├── begin
```

### 4. Семантичний терм (SEM-01) — `semantics/terms.py`, `semantics/builder.py`

Програма розглядається як функція, що перетворює стан змінних (наприклад `[M↦8, N↦16]`) на новий стан. Ця функція записується термом:

| Позначення | Значення |
|---|---|
| `n̄` | константа n |
| `x⇒` | значення змінної x |
| `S²(f, g1, g2)` | застосувати операцію f (`add, sub, mult, eq, gr, or`) до результатів g1 і g2; `S¹(neg, g)` — заперечення |
| `AS^x(a)` | присвоєння x := a |
| `f1 • f2` | спочатку f1, потім f2 |
| `IF(b, f1, f2)` | розгалуження |
| `WH(b, f)` | цикл |
| `id` | `skip` |

Терм будується рекурсивно з AST, по одному правилу на кожен вид вузла:

```
sem_P(begin S end)          = sem_S(S)
sem_S(x:=a)                 = AS^x(sem_A(a))
sem_S(S1;S2)                = sem_S(S1) • sem_S(S2)
sem_S(if b then S1 else S2) = IF(sem_B(b), sem_S(S1), sem_S(S2))
sem_S(while b do S)         = WH(sem_B(b), sem_S(S))
sem_S(begin S end)          = sem_S(S)
sem_S(skip)                 = id
sem_A(n) = n̄    sem_A(x) = x⇒    sem_A(a1+a2) = S²(add, sem_A(a1), sem_A(a2))
sem_B(a1=a2) = S²(eq, …)    sem_B(b1∨b2) = S²(or, …)    sem_B(¬b) = S¹(neg, sem_B(b))
```

```console
$ sipl term examples/gcd.sipl
WH(S¹(neg, S²(eq, M⇒, N⇒)), IF(S²(gr, M⇒, N⇒), AS^M(S²(sub, M⇒, N⇒)), AS^N(S²(sub, N⇒, M⇒))))
```

### 5. Обчислення на стані (SEM-02) — `semantics/state.py`, `semantics/evaluator.py`

Стан — це набір пар «змінна ↦ число». Присвоєння оновлює стан операцією накладання `∇`: `[M↦8, N↦16] ∇ [N↦8] = [M↦8, N↦8]`.

Терм застосовується до стану за правилами:

| Правило | Формула |
|---|---|
| AF_S | `S²(f, g1, g2)(st) = f(g1(st), g2(st))` |
| AF_AS | `AS^x(a)(st) = st ∇ [x ↦ a(st)]` |
| AF_SEQ | `(f1 • f2)(st) = f2(f1(st))` |
| AF_IF | `IF(b, f1, f2)(st) = f1(st)`, якщо `b(st)` істинне, інакше `f2(st)` |
| AF_WH | поки `b(st)` істинне, `st := f(st)` |
| AF_DNM | `x⇒(st) = st(x)` |
| AF_ID | `id(st) = st` |

Ключ `--trace` показує кожне застосоване правило:

```console
$ sipl eval examples/gcd.sipl -s "M=8, N=16" --trace
AF_WH   WH(…)([M↦8, N↦16]) = [M↦8, N↦8]   (ітерацій: 1)
  WH#0    st0 = [M↦8, N↦16];  умова = true
    AF_S    S¹(neg, S²(eq, M⇒, N⇒))([M↦8, N↦16]) = neg(false) = true
    ...
    AF_IF   IF(…)([M↦8, N↦16]) = [умова false] [M↦8, N↦8]
      AF_AS   AS^N(S²(sub, N⇒, M⇒))([M↦8, N↦16]) = [M↦8, N↦16] ∇ [N↦8] = [M↦8, N↦8]
  ...
значення визначене (↓): [M↦8, N↦8]
```

Можливі результати:

| Результат | Коли буває | Код |
|---|---|:-:|
| визначене (↓) | обчислення завершилося | 0 |
| не визначене (↑) | у стані немає потрібної змінної | 3 |
| не визначене (↑) | стан у циклі повторився, отже цикл нескінченний | 3 |
| невідомо | вичерпано ліміт кроків `--max-steps` | 4 |

### 6. Перевірка коректності (SEM-04) — `proof/spec.py`, `proof/assistant.py`

Що програма має робити, описується у файлі `.spec`:

```
pre:       M > 0 and N > 0
invariant: M > 0 and N > 0 and gcd(M, N) = gcd(old(M), old(N))
post:      M = N and M = gcd(old(M), old(N))
variant:   M + N
bound:     2
domain:    M, N in 1..15
```

| Рядок | Значення |
|---|---|
| `pre` | передумова: для яких вхідних даних програма має працювати |
| `post` | післяумова: що має бути після завершення |
| `invariant` | твердження, яке залишається правдивим після кожної ітерації циклу |
| `variant`, `bound` | величина, що зменшується на кожній ітерації, і її нижня межа |
| `domain` | значення змінних, на яких виконується перевірка |

`old(X)` — значення X на початку виконання. В умовах можна вживати `and or not ->`, порівняння `= != > < >= <=`, арифметику `+ - * / %` і функції `gcd abs min max fact pow div mod even odd`.

Перевірка відбувається так:

1. Терм програми розкладається на три частини: `F0 • WH(p, f) • F2` — код до циклу, цикл, код після циклу.
2. Формуються умови:

   | Умова | Що перевіряє |
   |---|---|
   | INIT | після `F0` інваріант виконується |
   | BASE | після виходу з циклу і `F2` виконується післяумова |
   | STEP | одна ітерація тіла зберігає інваріант |
   | BOUND | поки цикл триває, `variant ≥ bound` |
   | DECR | кожна ітерація зменшує `variant` |

   INIT, BASE і STEP дають часткову коректність (якщо програма завершилась, результат правильний). BOUND і DECR додатково доводять, що цикл завершується, тобто дають повну коректність.
3. Для кожної умови будується формула: присвоєння `x := a` у тілі циклу перетворюється на підстановку `x ↦ a`, розгалуження — на два випадки. Для GCD формула кроку виходить така:

   ```
   … ⇒ (M > N ⇒ M – N > 0 ∧ N > 0 ∧ gcd(M – N, N) = gcd(old(M), old(N)))
     ∧ (¬(M > N) ⇒ M > 0 ∧ N – M > 0 ∧ gcd(M, N – M) = gcd(old(M), old(N)))
   ```
4. Кожна формула перевіряється на всіх станах із `domain`. Якщо станів забагато, перевіряється випадкова вибірка.
5. Окремо програма запускається з кожного стану, що задовольняє `pre`, і на кожній ітерації перевіряється інваріант.
6. Якщо умова порушена, виводиться контрприклад:

   ```
   ✘ [BASE] База індукції (k = 0)
      формула: gcd(M, N) = gcd(old(M), old(N)) ∧ ¬¬(M = N) ⇒ M = gcd(old(M), old(N))
      КОНТРПРИКЛАД:
        st = [M↦-2, N↦-2]
        висновок хибний: M = gcd(old(M), old(N)) на стані [M↦-2, N↦-2]
   ```

**Обмеження.** Перевірка на скінченній області не є доведенням для всіх цілих чисел: успіх означає, що на цій області умови не спростовано. Інваріант і спадну величину задає користувач.
